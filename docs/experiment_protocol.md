# 实验协议：GPT-5.2 两种造题方式 vs PuzzleForge

本文件规定当前实验的设计、抽样和统计口径。操作命令见 [运行手册](gpt52_runbook.md)。

## 1. 指导思想

1. **验证而非证明。** 目标是得到可核查的比较结果，允许“无差异”“证据不足”或“baseline 更好”。
2. **单变量比较。** 三组使用相同种子、相同语言和相同答题格式；B 与 C 只差“直接出题”还是“写生成器”。
3. **不混淆历史与因果。** A 是论文流程筛选后的历史测试集，不是同模型、同预算重跑；结论限定在“固定种子与设置下的测试集比较”。
4. **生成与评价分离。** 生成阶段不看评测标签；盲评移除方法、seed、原生解释；自动初评只是代理，人工双审才是主终点。
5. **baseline 不能故意弱化。** B/C 用同一 GPT-5.2、同一预算和同等提示词投入；不靠弱 baseline 或窄提示词制造优势。
6. **失败保留、抽样固定。** 不删除失败槽位，不按质量补选，不因结果不理想换 seed。
7. **可复现优先。** 配置、提示词、代码、输入全部冻结 hash；任何改动新建 run。

## 2. 组别与规模

| 组别 | 来源 | 原始槽位 | matched |
|---|---|---:|---:|
| A：PF | 已有测试题，历史筛选数据 | Σ n_s | Σ n_s |
| B：direct | GPT-5.2 直接输出题目 JSON | 1940 | Σ n_s |
| C：framework | GPT-5.2 现场写 Python 生成器，本地执行 | 1940 | Σ n_s |

- `n_s` 是该 seed 在 PF 参考集中的题数；97 个 seed 合计 1,284。该值由 `manifest.json` 的 `matched_slots` 固定，可用 `records_selected.jsonl` 的 matched 统计复核。
- 两个 baseline 各 97 × 20 = 1940 个原始槽位；matched 之外的槽位为 extra，只做产量、重复率和稳定性补充分析。
- 每个 baseline 每个 seed 生成 20 槽；matched 槽位在生成前按固定 RNG 选定，不按题目质量挑选。

## 3. 种子与语言

129 个种子来自 `seed_puzzles.jsonl`。本轮使用语言控制池中的 **97 个 seed**，完整清单在 [configs/gpt52_seed_ids.txt](../configs/gpt52_seed_ids.txt)。

筛选规则：排除已用于提示词开发的 seed；要求该 seed 的所有 PF 参考题至少含 20 个中文字符。只看语言与可用性，不看题目质量，也不按模型结果挑选。

语言约定：

- `prompt_language=zh`：指令用中文。
- `output_language=zh`：题面、答案格式和 explanation 用中文。
- 不用英文输出与中文 PF 直接比较；语言会变成混杂因素。
- 以后改提示词，应另抽 holdout，不能把同一批 seed 同时当开发集和验证集。

## 4. 生成协议

### 4.1 共同输入

- 同一 `seed_question` 和 `seed_answer`；答案保留原 JSON 类型。
- 系统提示词为 `paper_v2` 所选语言的完整单文件，不再拼接旧 `quality.txt`。
- 质量目标覆盖 L1–L4：场景/问法、变量/约束类型、同类约束实例数量、具体值/查询目标。
- 不向 baseline 提供 PF 测试题、答案、完成品生成器或审核标签。

### 4.2 B：直接造题

每个 seed 分 4 批，每批 5 道；后续批次看到自己已生成的题面，用于去重。模型直接输出 `problem`、`answer`、`explanation`。每批最多 3 次生成/修复；失败记 `generation_failed`，保留槽位。

### 4.3 C：GPT-5.2 现场写生成器，再执行

这一组没有预置的 per-seed 生成器。`framework.txt` 只是 system prompt；每个 seed 的 Python 代码来自该 seed 的 API 响应，原样保存后再执行。运行器只负责 stdio、sandbox、探针和修复循环，不提供任何题目生成逻辑。

每个 seed 请求一个可复用 Python 程序：

- stdin：`{"seed": 整数, "count": 正整数}`；
- stdout：恰好 `count` 个题目对象；
- 必须支持不同 seed/count，用局部 `random.Random(seed)`，不得硬编码 20 道完成品；
- 运行时不联网、不调 API、不启动子进程。

首次执行先用另一个采样 seed 生成 3 道并重复一次，检查确定性；探针不进入正式数据。通过后用固定采样 seed 生成 20 道。每 seed 最多 3 次完整代码尝试，修复时提供真实语法/运行/格式错误。程序在 macOS `sandbox-exec` 中运行；隔离不可用时明确失败。

### 4.4 模型与预算

配置：[configs/gpt52_paper_v2_20261028.json](../configs/gpt52_paper_v2_20261028.json)。

| 项目 | 值 |
|---|---|
| model | `gpt-5.2-2025-12-11` |
| 参数 | `max_completion_tokens=32768` |
| HTTP 等待/重试 | 300 秒 / 3 次（计入请求上限） |
| 首次生成请求 | 约 485（direct 388 + framework 97） |
| 生成请求硬上限 | 2000 |
| 并发 | 8 seeds |
| 生成/修复 | 每批或每 seed 最多 3 次 |

两组使用同一模型、参数和 token 上限。端点不支持某参数时明确失败，不静默删除参数或换模型。若要加 `reasoning_effort`，在首次 `prepare` 前对称加入并冻结。

## 5. 盲评协议

- 每 seed 每方法固定抽 5 题；97 × 3 × 5 的上限是 1455，实际数量由各 seed 的 matched 配额决定。
- 不全部盲评的原因：三组 matched 共 3,852 题，全部评审即使 k=1 也需约 7800 次请求；5/seed/组 在 97 个 seed 上约 1400 题，既超过 1000，又保留 seed 配对和覆盖。
- 抽样用固定 RNG，包含生成失败槽位，不按质量挑选；`--min-audit 1000` 会在低于 1000 时直接失败。
- 不允许为了凑 1000 按质量补题；若配额不足，只能提高 `--per-seed`。
- `audit_blind.jsonl` 只含 `anon_id`、`problem`、`answer`；方法、seed、原始 id、原生解释全部移除。私有映射留在 `audit_key.jsonl`。
- 解题请求只见题面；评审请求才提供题面、canonical answer 和匿名解题证书。
- 评审模型可返回 `valid`、`invalid`、`uncertain`；三次 schema 修正仍失败记执行未决；网络/鉴权/预算错误停机，不算题目错误。
- 优先使用与生成模型不同的评审模型。只有 GPT-5.2 时标为“自评/单模型初评”，只能作探索性证据。
- 自动标签与人工标签分开；自动标签不得代填 `audit_labels.csv`。

自动初评规模：

| 配置 | 成功请求 |
|---|---:|
| 单模型 k=1 | 约 1400 × (1+1) = 2800 |
| 单模型 k=4 | 约 1400 × (4+1) = 7000 |
| 两个模型 k=4 | 约 1400 × (2×4+2) = 14000 |

## 6. 指标

| 维度 | 操作定义 | 不能替代它的指标 |
|---|---|---|
| 产量 | 目标槽位、有输出、成功唯一题、失败率 | 请求数不等于好题数 |
| 正确性 | 独立复核题意完整、无矛盾、可解、答案一致 | 自写求解器通过率、模型自评分 |
| 自动有效性代理 | 评审模型 valid/invalid/uncertain；全部 valid 才为共识 valid | 模型共识不是真值 |
| 词面多样性 | 规范化精确重复、同 seed 4-gram 近重复（单位匹配版本见 rebuttal T11） | 词面不同不等于结构不同；seed 级会混入 PF 的多生成器效应 |
| 结构/语义多样性 | 固定标签下的场景、变量/约束类型、推理操作覆盖 | 标签代理不是真实结构证明 |
| 推理深度 | 人工最短必要依赖步骤；自动 0–4 代理 | 解释字数、token 数、程序行数 |
| 有效题难度 | 固定解题面板 avg@k，越低越难 | 无解/错答案造成的低准确率不叫难 |
| 证书可核查度 | 统一解题器证书盲评 0–4 | 不等于原生解释存在率 |
| 成本 | 请求、token、重试、墙钟 | 缺历史成本时不补造金额 |

注意：PF 每 seed 有 3-4 个生成器，B2/B1 每 seed 1 个。seed 级的 near-dup 与零产出不是同口径；rebuttal 同时报告生成器级与 one-generator-matched（T8、T11）。

深度锚点：0=抄取；1=单步推断；2=两步必要依赖；3=至少三步相互依赖并混合操作；4=必要分类讨论/长约束证明。证书评分：0=错误；1=关键论断无支撑；2=部分可核查；3=主要步骤可核查但有小缺口；4=完整正确可核查。

## 7. 统计与结论边界

- 先报告绝对值、分母和每 seed 宏平均差；PF−direct、PF−framework 分别比较。
- 主分析以 seed 为聚类单位，固定 RNG、2000 次配对 bootstrap、95% 区间；不能把 1000+ 题当独立观测。
- 自动初评单独报告代理指标和相同聚类原则下的区间，不与人工主终点合并；`uncertain` 单列并给出敏感性上/下界。
- 深度、难度、证书只在有效且可评估子集比较，必须显示排除比例和覆盖。
- 当前不做多重检验校正，也不作显著性断言；若论文要用显著性措辞，需预注册两项主比较并做 Holm 校正。
- 覆盖不全时只描述被覆盖子集，不外推全体。

报告句式（数字由产物填入）：

> 在固定 97 个 seed 与 GPT-5.2 设置下，PF 在 X 指标上较 direct 高 Δ、较 framework 高 Δ；Y 未发现差异或证据不足。自动初评覆盖约 1400 题，其中有效判定 N 题；配对 bootstrap 区间为……。结果受历史 PF 数据、语言控制和单次生成限制，不能解释为框架的普遍因果优势。

## 8. 产物与复现

```text
manifest.json             配置、输入/prompt hash、匹配槽位
snapshot/                 冻结的代码、提示词、输入
api_cache/                请求/响应、usage、重试
traces/                   实际发送的 messages（含修复）
results/                  B/C 分批结果
programs/                 C 的代码、探针、accepted
records.jsonl             全 129 seed 记录
records_selected.jsonl    97 个语言控制 seed 子集
audit/                    1000+ 题盲评、私有 key、人工表
auto/                     自动初评、auto_report.md、examples.jsonl
generation_costs.json     生成阶段用量
evaluation_costs.json     自动初评用量
```

复现分两层：用保存的响应、生成器、随机 seed 离线重放；或重新请求同一服务。API 不保证逐字相同。配置、输入、代码或提示词改变时必须新建 run；端点重试失败属于基础设施问题，不能计为“模型生成了坏题”。

当前只执行 97 个语言控制 seed；不是全 129 seed。代码中的全量 `pipeline` 保留，但硬编码 6880 槽位和 2000 产量目标，不作为本轮流程。
