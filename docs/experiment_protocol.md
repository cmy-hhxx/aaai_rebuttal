## 1. 已确认的范围与结论边界

本实验比较三种数据来源，重点评估题目质量，不进行下游 RL 训练。实现的新代码只有两个 baseline 及统一评测工具，**不重写、不冒充论文原有五 agent 实现**。

已确认的选择：

- A：直接使用投稿附件中现有的 PF-86K 测试题 **1720 道**（Normal 862、Hard 858），不另补造。
- B：API 模型直接生成题目，129 个原始种子 × 20 道 = **2580 个目标槽位**。
- C：API 模型为每个原始种子编写可复用的程序生成器，由程序本地采样 20 道；129 × 20 = **2580 个目标槽位**。
- 两个 baseline 优先使用论文相同的 **GPT-5.2 快照 `gpt-5.2-2025-12-11`**，然后按同一协议扩展其他模型。
- 第一轮先全自动初评，独立人工复核以后补。自动评审结果与人工真值严格分开保存。

总规模为 1720 + 2580 + 2580 = **6880 个记录槽位**。目标槽位不等于成功生成数、唯一题数或有效题数；失败和重复都保留。禁止通过删掉失败记录或事后更换种子来宣称已达标。若任一 baseline 成功唯一题不足 2000，报告“产量目标未达成”，不得凑数；需要扩充时建立新的补充实验，不改已冻结主实验。

目标假设是 A 相比 B、C 产生更高质量的数据；**是否成立由结果决定**。允许结论为支持、部分支持、未发现优势、baseline 更好或证据不足。不能预先承诺所有维度胜出，也不能从有限模型推断“任何模型生成的数据都不如我们”。

**历史数据限制：**A 已经过论文中的生成器验证、过滤和测试集选择，不能取得其完整拒绝样本、成本及重试记录。即便 B、C 使用相同 GPT-5.2，三组也不是从头同步运行的、完全控制模型及预算的因果实验；原论文还使用 DeepSeek-V3.2 做 solving/filtering。本轮能直接支持的是“固定 PF 测试集与新生成 baseline 的质量比较”。若要严格证明完整框架优于其他方法、或某 agent 必不可少，还需原实现重跑／组件消融。题目质量实验也不能替代审稿人 CYZC 提出的同等 RL 预算下游训练比较。

## 3. 主比较如何配平

1720 道 A 题来自 129 个种子，每个种子实际有 4–16 道，不能用“随便取 1720 道 B/C”来比较。

1. 从 A 统计每个 seed 的题数 `n_s`；主实验每个方法在该 seed 均使用 `n_s` 个槽位，共 1720／方法。
2. B/C 每 seed 仍生成 20 道。用固定 RNG `20261028` 和 seed id 在生成前选定 `n_s` 个 matched 槽位；其余为 extra。按完整 manifest 保存，禁止按题目好坏挑选。
3. 主表只比较 matched 的 1720 × 3 = 5160 个槽位。B/C 额外各 860 个槽位用于产量、重复率和稳定性补充分析，不能混进主表使样本量失衡。
4. 三组统一英文题面、相同种子分布、相同答题格式要求。只给 B/C 原始 seed，不给 A 测试题、答案、完成品生成器或审核标签。
5. 不按 A 的 Normal/Hard 比例事后筛选 B/C；论文规则难度不能直接跨方法照搬，难度用新的统一解题面板测量。
6. 每种方法均汇报每 seed 宏平均和全量微平均。主统计按 seed 配对；同一生成器的题不是独立重复实验。

第一轮为一个固定采样 run；单次生成的局限需明示。扩展稳定性实验可使用额外 2 个 RNG／新生成调用 run，每个 run 独立目录、单独预算；不能把重复 run 当作新增 seed。

## 4. 两个 baseline 的具体方法

| 项目 | B：直接造题 | C：模型编写生成器后造题 |
|---|---|---|
| 输入 | 同一 seed question + seed answer + 统一质量 brief | 完全相同输入，另加执行接口、可用依赖及运行限制 |
| 输出 | 题面、答案、简短可核查解答证书 | 可执行 Python 程序；程序输出同样字段 |
| 每 seed 生成量 | 4 批 × 5 道；后续批次可看到自己的已生成题以去重 | 一个模型编写的可复用生成器，采样 20 道 |
| 自检能力 | 明确允许模型规划、检查一致性和答案后输出 | 模型可自由设计生成、校验、枚举、求解、自测等内部模块 |
| 修复 | 每批最多 3 次输出尝试，提供格式错误反馈 | 每 seed 最多 3 次完整代码尝试，提供真实运行／格式错误反馈 |
| 语义架构 | 不强加额外 agent | 不强制 DSL、五 agent、单种模板或仅随机换值 |
| 库 | 不需要运行代码 | Python 3.12 + 标准库 + 固定版本 SymPy、Z3 |
| 限制 | 不使用 A 的已完成题目 | 代码运行阶段不联网、不再调用 API；API 负责写生成程序 |

C 在接口层使用“一个 seed 对应一个 Python 程序”，129 个程序及统一任务清单组成生成器集合；程序内部可有任意合理的函数、类和多个生成族。这对应审稿人所指的 **direct LLM generation of executable generators**。它不是声称“一次提示就让模型发明通用造题 agent 系统”；如果另比较模型设计的 API 多轮 agent 框架，应作为 C-agent 独立扩展组，不能与本组混称。

执行接口：stdin 为 `{"seed": 整数, "count": 正整数}`；stdout 为完整 JSON 数组，每项含 `problem`、`answer`、`explanation`。程序必须支持不同 count 和随机种子，不能硬编码 20 道完成品。正式采样前使用另一个随机种子生成 3 道，并重复一次检查确定性；探针不进入正式数据。代码、探针、最终采样种子和报错全部保存。

两条路径使用同一 generation model、相同请求参数／token 上限，并认真编写高质量提示词。每次最多 `32768 max_completion_tokens` 是初始配置，先做协议兼容性和独立开发例子试跑；不足时应**在正式冻结前**对称调整，不能只放宽赢家。只在独立开发题上调提示词，不依据主实验胜负反复优化。服务不支持某参数时明确失败，不静默删除、换模型或改为另一 API。

## 5. 评价指标与操作定义

正确性／有效性是主要质量终点；其他维度分别报告，禁止用任意加权总分掩盖某维度失败。

| 维度 | 指标、分母和具体定义 | 不能替代它的指标 |
|---|---|---|
| 产量 | 目标槽位、有输出、成功唯一题数、失败数／率；达到 2000 成功唯一题才算 baseline 产量达标 | 请求 2580 次不等于获得 2580 道好题 |
| 正确性 | 独立复核题意完整、无矛盾、可解、参考答案与题面和答案类型一致；错误分为缺条件、歧义、无解、错答案、渲染失真等 | 自己的求解器通过率、模型自评分、执行成功 |
| 自动有效性代理 | 评测模型各自判 valid/invalid/uncertain；全部 valid 才为共识 valid；报告分歧率和保守／乐观界 | 模型共识不是真值；uncertain 不能全部当成“题目有错” |
| 词面多样性 | NFKC + casefold + 空白归一化的精确重复率；同 seed 词／标点 5-gram Jaccard ≥ 0.85 的近重复题占比 | 词面不同不等于推理结构不同；5-gram 不叫语义多样性 |
| 结构与语义多样性 | 固定标签下的场景、变量／约束类型、推理操作覆盖；标签熵 `H=-Σp log2p`、结构标签组合数；自动初评用 judge 标签代理 | 不把每个数值采样都算一个新结构；不把标签代理当已证明的真实结构 |
| 语义嵌入（可选扩展） | 冻结 embedding 模型／版本，固定长度处理与聚类阈值，比较等样本量下簇数、有效簇数、距离；当前脚本未实现，不能先填结果 | 不用不同模型或不同阈值分别照顾各组 |
| 推理深度 | 人工复核最短充分证明的必要依赖步骤和依赖链；自动版用 0–4 档有证据的深度代理 | 解释字数、输出 tokens、程序行数、搜索耗时 |
| 有效题难度 | 与生成不同的固定解题模型面板，每题每模型独立采样 k=4；`avg@4=(1/4)Σ正确指示`，越低表示对该面板越难 | 无解／错答案造成的低准确率不叫高难度；avg@4 不叫 pass@4 |
| 解答可核查度 | 给三组相同解题器预算生成统一解答证书，再盲评其正确性、关键约束覆盖、步骤可复核程度 0–4；汇报可评估覆盖 | 自动指标衡量统一证书的可核查度，不等于原生生成过程可解释性 |
| 原生产物可审计性 | 分别展示原始题面、答案、原生解释是否存在、生成器与采样参数是否可追溯；代码可追溯性作为独立描述 | 不能直接给“有 DSL”的方法加解释性分；PF 没有原生解释应记 NA |
| 成本 | B/C 实际调用数、tokens、重试数、墙钟时间、成功唯一题／token；金额只有配置真实单价后计算 | A 历史成本缺失，不补造等成本优势 |

深度代理锚点：0=抄取／查找；1=单步直接推断；2=两步必要依赖；3=至少三步相互依赖并混合操作；4=必要的分类讨论／分支推理或长的相互作用约束证明。必须保存具体依赖证据，不能只返回分数。

解释证书评分：0=错误；1=关键论断无支撑；2=部分可核查；3=主要步骤可核查但有小缺口；4=正确且完整可核查。不同任务答案可能是一个解、解集合、计数或真假判断，按题目声明审核，不一律要求唯一赋值。

## 6. 自动初评与后续人工复核

所有 6880 个槽位先做统一的格式、缺失、重复和产量检查。高成本的解题／质量面板使用**生成前固定规则抽取的 matched 子样本**：每个 seed 每个方法 2 道，共 129 × 3 × 2 = **774 道**。抽样包括失败槽位，不根据模型解题结果挑选。不能将 774 道的结果写成“已逐题验证全部 6880 道”。

自动流程：

1. 去掉方法名、source、seed id、generator id、原始 id 和原生解释，打乱匿名题目。私有映射只在本地聚合和追踪案例时使用。
2. 解题请求**只见题面**，不见 canonical answer、PF 配置或任何生成器。每个 panel 模型做 4 次独立请求，保留答案和简短可核查证书。
3. 质量评审阶段才提供题面、canonical answer 和匿名解题证书；评审模型必须独立核查答案，可返回 uncertain；不能假定 canonical answer 永远正确。
4. 相同面板和参数应用于三组。优先至少两个不同、独立于生成器的模型；只有一个可用模型时运行单模型版，明确降级为探索性初评。同一模型反复调用不算独立模型面板。
5. 难度仅在共识有效题上算；对每次答案比对仍有分歧／unknown 的题，难度记 NA，并报告排除和覆盖比例。难题被判 uncertain 的选择偏差需要讨论。
6. 模型名、system fingerprint（若返回）、完整 prompts、请求／响应、usage、重试和文件 hash 全部留档。标签与评分不反馈到生成流程。

774 道、2 个 panel 模型、k=4 的配置，约需 `774 × (2×4 + 2) = 7740` 次成功请求；HTTP 重试另计。单模型为 3870 次。明天应先确认端点支持的模型及预算上限，再运行全量评测；可以先做小规模兼容性 smoke test，但不能用主实验结果反复调 prompt。生成与评测预算分开记录。

后续人工审核沿用同一 774 道匿名表，两人独立标注，分歧第三人裁决；未决项不算主终点已审核。人工标签保存在 `audit_labels.csv`，模型标签保存在 `model_labels.jsonl`，禁止把模型评分填入人工审核表。报告审核一致率／分歧率、各方法各 seed 的覆盖，以及缺条件、歧义、答案错误和渲染失真案例。

人工正确性／深度包同样移除原生解释，避免 PF 缺少 explanation 而暴露组别；原生解释单独存私有文件。第一轮人工表的 explainability 留空。若人工进一步验证统一解答证书，应另建同规格证书审核包；不得把它与“原生解释存在率”混为一项。

## 7. 统计与可支持的结论

- 全部先报告绝对值、样本分母和每 seed 宏平均差；PF-B、PF-C 分别比较。
- 人工有效率的主分析以 seed 为聚类单位做配对 bootstrap，固定 RNG、2000 次重采样、95% 区间；不能把 2580 道同模板题当 2580 次独立实验。
- 自动初评单独提供模型代理指标和相同聚类原则下的描述区间，不能与人工主终点合并。uncertain 单列，并对有效性代理提供敏感性边界。
- 深度、难度、证书评分只在有效且可评估的子集比较，必须显示各组排除比例，避免只剩容易题的组看起来“更正确”。
- 现有脚本不给多重检验校正后的显著性断言。若论文使用显著性措辞，需预注册两项主比较并做 Holm 校正；其他维度标为次要／探索性。
- 标签覆盖／熵只在同样大小或配平子集比较；原始规则难度和自动面板难度分开，不混成总分。
- 每个额外生成模型分别跑 B/C，同样种子、配额和协议；注明 A 仍是历史固定参照。至少测试两个具体模型才有跨模型实证，结论仅限测试模型，不写“无论任何模型”。

## 8. 结论报告与具体案例

最终生成两层报告：自动阶段 `auto_report.md`（明确标记初评）、人工阶段 `report.md`。至少包括：

1. 三组规模、实际成功唯一题、失败和重复情况，主表与 extra 分开。
2. 正确性／共识代理、结构与语义标签、深度、有效题难度、证书可核查度的分项表及覆盖。
3. 每项 PF-B、PF-C 的绝对差、适用样本和不确定性；结果不支持的维度直接写“不支持／证据不足”。
4. 案例包含同 seed 的三种数据来源：完整题面、答案、可核查解答、具体约束和依赖结构、评测证据、原始文件／行号、代码／采样种子（如有）。同 seed 不意味着是相同问题，不能用题面不同直接归因为方法优劣。
5. 按固定顺序从真实结果选取“支持 PF 优势”“相近”“反驳 PF 优势”的同 seed 案例；没有某类型就说明缺失，不编造、不只挑赢家。自动案例必须人工核实后才能写入 rebuttal 的确定性论证。
6. 对优势给出可检查的机制解释，如缺失约束、答案与题面不符、单纯换数字、必要推理依赖增加、证据覆盖更完整；不能只说“看起来更复杂”。

可用结论句式：“在固定的 129 个种子及本次模型／预算设置下，PF 测试题在 X 指标上较直接造题高 Δ，较模型编写生成器高 Δ；Y 未发现优势。自动初评／人工复核覆盖 N 道，区间为……。以下同 seed 案例展示了具体差异。”所有数字必须由运行产物填入，当前尚无实验胜负结论。

## 9. 可复现实现、运行约定和明天的输入

实现文件：

| 文件 | 功能 |
|---|---|
| `experiment/run.py` | 读取真实种子、保留混合答案类型、固定主表配额和槽位、执行 B/C、续跑及导出 |
| `experiment/prompts/*.txt` | 两方法共用质量 brief，以及完整方法提示词；冻结 hash |
| `experiment/api.py` | OpenAI ChatCompletion 兼容调用、缓存、完整请求／响应、重试、请求上限、密钥脱敏 |
| `experiment/executor.py` | 无网络、无密钥的 macOS 隔离运行器；不把生成代码 import 到主进程 |
| `experiment/metrics.py` | 固定规则的词面近重复统计；不伪称语义评测 |
| `experiment/costs.py` | 从真实调用日志汇总用量与 API 耗时；不补造价格或缺失用量 |
| `experiment/pipeline.py` | 一条命令串联生成、产量达标检查、匿名抽样和可选自动初评 |
| `experiment/evaluation.py` | 固定匿名抽检、人工审核表、独立标签统计与配对区间 |
| `experiment/autojudge.py` | 匿名模型解题／评审、代理指标、自动报告与真实案例候选 |
| `configs/experiment.example.json` | 模型、端点、随机种子、预算、token、运行器配置 |
| `runtime-requirements.lock` | 实际安装的 SymPy／Z3／mpmath 版本 |

ChatCompletion 接口使用 [OpenAI 官方接口定义](https://developers.openai.com/api/reference/python/resources/chat/subresources/completions/methods/create)：POST `/chat/completions`，`model/messages/stream:false`，实际返回能力以明天端点为准。支持 `/v1` base URL 或完整路径；不会静默改用其他 API。参数支持随模型变化，需先做兼容性检查。

明天需提供：端点 URL、可用的 model id、鉴权方式／环境变量中的 key、允许的生成和评测请求预算；若希望两个不同评测模型，还需它们的 model id／可访问服务。URL 本身不一定包含模型或认证信息。API key 只放环境变量，不写入配置、日志或 Git。

复现分两层：①利用保存的响应、生成器、随机种子离线重放；②重新请求同一服务的统计复现。API 调用不能承诺逐字确定性，即使提供 seed。配置、输入数据、代码或 prompts 改变时必须新建 run 目录，不混用旧结果；端点重试失败属于基础设施问题，不能计为“模型生成了坏题”。

macOS 本机运行已准备独立 Python 3.12 环境。隔离器若因外层工具沙箱限制无法启动，必须在允许启动 sandbox-exec 的环境运行；**绝不回退到裸跑模型代码**。换机器需重建相同版本依赖；Linux 需要另实现并验证容器执行器，当前不宣称跨平台即插即用。

命令和产物见项目 `README.md`。当前没有调用付费生成 API，没有新造真实实验题，也没有填入预设结论。
