# Rebuttal 论证草稿：PF 的优势该怎么写（1000+ 题 run）

> 数据：`runs/gpt52_final_20261028`（97 seeds / 每组 1284 matched / 1440 道盲评）。生成 gpt-5.2，评审 gpt-5.6-luna 单模型 k=1。完整报告：`final_experiment/run/REPORT_1000.md`。

## 0. 口径

| 组别 | 有效率 | 条件有效率 | 深度 | 题面中位 | token/有效题 | $/有效题 |
|---|---:|---:|---:|---:|---:|---:|
| PF | **0.76** | 0.763 | **2.94** | **692** | 1,227 (@200) / 12,267 (@20) | — |
| direct | 0.28 | 0.280 | 1.93 | 297 | 4,571 | 0.112 |
| framework | 0.73 | **0.774** | 2.34 | 321 | **527** | **0.017** |

配对差：PF − direct = **+0.48 [+0.41, +0.56]**；PF − framework = **+0.03 [−0.05, +0.11]**。

- 可以写：PF 对 direct 全面更好（有效率、深度、信息量、重复率、成本）。
- 可以写：PF 对 framework 深度更高、题面更长、重复更低、边际成本为零。
- 不能写：PF 的有效率显著高于 framework；按“有题面”条件口径，framework 0.774 反而略高于 PF 0.763。

## 1. 多样性/重复性

同一 seed 内，字符 4-gram 相似度超过阈值的题对占比：

| 阈值 | PF | direct | framework |
|---|---:|---:|---:|
| 0.5 | 18.4% | 35.8% | 70.4% |
| 0.7 | 7.4% | 16.8% | 46.4% |
| 0.8 | **3.0%** | 6.2% | **24.9%** |

按 seed 的坍缩比例（ECDF）：

| 组别 | seed 数 | 重复率 ≥50% | 100% 重复 |
|---|---:|---:|---:|
| PF | 97 | 1 | 1（`logic_3`，只有 4 题） |
| direct | 97 | 3 | 2 |
| framework | 92（5 个失败） | **21** | **11** |

新颖度：direct 从 0.40 升到 0.65（第 6 题后越过 PF 参考线 0.55）；framework 从 0.59 升到 0.72。**direct 随题量增加向 PF 的重复水平靠拢，framework 从一开始就更高。**

建议写法：

> 生成器式 API 造题在同一 seed 内明显坍缩：framework 有 21/92 个 seed 的题对近重复率 ≥50%，11 个 100% 重复；direct 也有 3/97 个 seed 坍缩，整体 0.8 阈值重复率 6.2%，是 PF 的 2 倍。PF 只有 1 个 4 题的小 seed 达到 100%。

不要写“API 造题 20 题就全重复”——绝大多数 seed 没有全重复；要写“尾部 seed 坍缩 + 整体重复率翻倍”。

## 2. Token 成本与 Pareto

| 阶段 | 请求 | token | 费用 |
|---|---:|---:|---:|
| direct 生成 | 391 | 2,474,140 | $14.97 |
| framework 生成 | 116 | 749,530 | $6.10 |
| 评审解题 | 1,421 | 2,833,651 | $2.56 |
| 评审判定 | 1,474 | 3,514,017 | $2.23 |
| 合计 | 3,402 | 9,571,338 | $25.86 |

- direct 1,279 token/题、6,963 token/matched 有效题、$0.112/有效题。
- framework 407 token/题、836 token/有效题、$0.017/有效题。
- 评审占 **66.3%** 的 token：造题便宜、筛选贵；这是 Pareto 图的主结论。
- framework 的生成成本与题量脱钩（一份生成器）；direct 线性增长。
- **PF 的 spec 成本（补测 10 seeds）**：187k token/generator、$0.098；按 200 实例摊销 935 token/题（1,227/有效题），按 20 实例摊销 9,353（12,267/有效题）。
- 每道有效题的 token 排序：framework 527 < PF@200 1,227 < direct 4,571 < PF@20 12,267。**成本不是 PF 的优势**；PF 只在“每个生成器摊几百个实例”时比 direct 便宜。

注意：PF 历史美元成本不可得，只能写“边际 API 成本 ≈0”。

## 3. 其他角度

| 维度 | 证据 | 支持谁 | 强度 |
|---|---|---|---|
| 推理深度 | 2.94 vs 2.34 vs 1.93 | PF | 强 |
| 题面信息量 | 692 / 321 / 297 字符 | PF | 中强 |
| 有效率 | 0.76 / 0.73 / 0.28 | PF vs direct；与 framework 打平 | 强 vs direct |
| 多样性 | 0.8 阈值 3.0% / 6.2% / 24.9%；21 个 framework seed 坍缩 | PF vs framework | 强 |
| 失败语义 | direct 344/480 invalid 但仅 1 题无输出；framework 5 个 seed 完全失败 | PF（验证/筛选） | 中强 |
| 可复现/可审计 | PF 生成器是版本化代码；framework 是单次 API 产物；direct 无生成器 | PF | 强（定性） |
| 证书分 | 3.12 / 3.32 / 3.72 | direct 略高 | 不利，别主动提 |
| 覆盖控制 | 生成器可指定约束类型/数量；采样靠碰运气 | PF | 中（定性） |

“失败语义”单独一段：direct 的 0 失败是假象，344/480 判 invalid 是静默坏数据；framework 有 5 个 seed 完全写不出可用生成器（100 个槽位失败），但至少是显式失败；PF 是生成后验证/筛选。

## 4. 推荐叙事

1. **direct 不可用**：有效率 0.28，344/480 invalid，深度 1.93，6.2% 近重复（2 个 seed 100%），$0.112/有效题。
2. **framework 证明了生成器路线，但浅、重复、且有 5% 的 seed 完全失败**：有效率 0.73（条件 0.774），成本最低（836 token / $0.017 每有效题），但深度 2.34、题面 321 字符、24.9% 近重复、21/92 个 seed 坍缩。
3. **PF = 工程化生成器 + 验证**：有效率 0.76、深度 2.94、题面 692 字符、重复率 3.0%；实例生成边际为 0，但 spec 构造成本 187k token/generator，按 200 摊销仍为 1,227 token/有效题，高于 framework。对 framework 有效率的 +0.03 不显著，但在深度、多样性、信息量、稳定性上更好。

一句话：

> 在同一 seed 与题量下，API 直接造题正确率崩，模型现写生成器则浅、重复且在 5% 的 seed 上完全失败；PF 的工程化生成器 + 验证流程在有效题率、推理深度、题面信息量和多样性上同时占优，并把边际生成成本降到 0。

## 5. 不能写

- PF 在有效率上显著优于 framework（+0.03，CI 跨 0；条件口径略负）。
- “API 造题 20 题就全重复”（只有尾部 seed 坍缩）。
- 单 judge、k=1 的显著性断言。
- PF 历史数据的因果结论。
- PF 比 baseline 便宜 X 美元（只能写边际 token）。
